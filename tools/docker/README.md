# Isolated native PHP8.5 + MySQL QA — prepared, NOT executed here

This harness is development/test tooling, **not a Hostinger deployment**. PHP8.5 is the chosen host-parity QA target; the application still declares PHP^8.4. Native images, dependency resolution and full tests have not run in Arena. Do not interpret source/guard tests as Docker/Pest/PDF/MySQL acceptance.

## Prerequisites — do not skip

1. A capable authorized machine with Docker Engine + Compose v2, Python3 and access to official image/dependency registries. No production DB, credentials, uploads or backup mounts.
2. A reviewed exact source candidate on the existing branch. Preserve unpublished changes; don't reset/clean/add-all to make the preflight green. QA of a dirty candidate is not proof of the published candidate.
3. **Both genuine, compatible Composer locks** generated by real Composer, reviewed and versioned. Root/platform production packages/versions/source references must agree, with matching production manifests. Do not copy or fabricate a content-hash. The root lock is no longer ignored. The helper checks only metadata; native Composer validates freshness/requirements.
4. No original root/platform `.env`, `.env.testing` or `.env.production` files in the QA source. Guards inspect existence only, not contents. Do not delete/rename a real env to evade this check: use a safe source-only QA view without private runtime data. The read-only container view is not source recovery or a new branch.
5. Review/pin official image digests on that machine before adopting a release pipeline. The prepared PHP8.5/Composer2/MySQL8.4 tags are not a verified digest-pinned release.

## Safe topology

- `php-deps` has the dependency-download network, **no DB environment**, no original env files, and runs Composer with plugins/project scripts disabled. It validates both locks before installing into the dedicated vendor volume. It does not boot Laravel.
- `php-test` and `mysql-test` share an **internal-only network**. They have no host ports or production mounts. Real provider egress is unavailable there; an unexpected live request must fail, not contact a customer.
- MySQL data is tmpfs with a disposable schema/user. The source is read-only; vendor and synthetic Laravel storage are separate QA volumes. Bootstrap cache and `/tmp` are fresh tmpfs in each test container, not a stale deployed config cache.
- Test entry checks explicit QA mode, database/schema/user/socket/URL, side-effect drivers, public dummy key, absent runtime env files and locks **before any app command**. Private credential/path/PHP/Composer overrides are rejected without printing their values.
- Only the offline test container may activate explicitly allowlisted Composer plugins to prepare vendor metadata. No project scripts or dependency install occurs there. Native runtime/extensions and platform requirements are checked again.
- Tests may recreate **only the disposable QA schema**. There is no cron, queue daemon, provider send or live restore command in this harness. PHPUnit config/bootstrap/extension overrides are rejected.

## Commands on that capable machine — NOT production

```sh
# Read-only source/native prerequisites. Exit2 is an honest HOLD, not a reason to reset source.
node tools/release/preflight.mjs

# Creates only tools/docker/.env with new random QA-only credentials; existing file remains intact.
sh tools/docker/setup-env.sh

docker compose --env-file tools/docker/.env -f tools/docker/compose.yaml config --quiet
docker compose --env-file tools/docker/.env -f tools/docker/compose.yaml build php-deps php-test
# The run starts mysql-test and requires php-deps to complete successfully first.
docker compose --env-file tools/docker/.env -f tools/docker/compose.yaml run --rm php-test --compact
# Stop the QA services. Do NOT add -v casually: it deletes QA artifacts/volumes.
docker compose --env-file tools/docker/.env -f tools/docker/compose.yaml down
```

Current missing locks/native runtime deliberately prevent a green result. No genuine lock files, installed app dependencies or native test results were produced by this readiness preparation.

Focused example: append `tests/Feature/Accounts/PaymentPostingRepairTest.php --compact` to `run --rm php-test`. The configured suite contains all existing Unit/Feature/Arch paths. The test APP_KEY is a public fixture, never usable for owner data. Output/logs must contain synthetic records only; review before publishing artifacts.

## Still separate gates

A serial native MySQL suite does not prove concurrent independent-process races, crash recovery, PDF/browser rendering or realistic scale. Native tests may expose further source/read-only-mount assumptions; fix/review those rather than relaxing isolation or copying owner data. Full PHPStan/Pint/security/build identity/browser acceptance remains open.

A complete private production backup/isolated restore is a **different** operation, documented in [the operator checklist](../release/PRIVATE_BACKUP_RESTORE_CHECKLIST.md). It is not performed by this harness. No production migration/import, provider test, merge or deployment follows automatically from a pass.
