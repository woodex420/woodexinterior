## B. Technical decisions

| ID | Decision | Why |
|---|---|---|
| **D-07** | **One Laravel 13 application** (modular monolith). Repository layout: `platform/` (the app), `docs/` (plans), `woodex/` (current static site, untouched until the website cut-over in P6). | One codebase, one deploy, one database. Fits shared hosting. |
| **D-08** | **PHP 8.4** in production and CI. Hostinger hPanel offers PHP 8.2–8.5 (8.3 default), so select 8.4 per site. | Laravel 13 needs ≥ 8.3. Current Spatie/Pest releases need 8.4. |
| **D-09** | **Livewire components are class-based** (`app/Livewire/**` + `resources/views/livewire/**`). Emoji filenames are switched off (`make_command.type=class`, `emoji=false`). | ASCII-only paths are safe for Hostinger File Manager, zip and FTP. Classes are easier to test and give AI agents a predictable pattern. |
| **D-10** | **Front-end build = Vite 8 + Tailwind CSS 4.3 + laravel-vite-plugin 3** (Laravel 13 skeleton defaults) **+ Preline 5**. Assets are built locally or in GitHub Actions; `public/build` is shipped. **No Node.js on the server.** | Hostinger shared hosting has no Node runtime. |
| **D-11** | **Do not load Alpine twice.** Admin pages get Alpine from Livewire 4 (bundled). Public pages do not load Livewire; they load a small Alpine bundle of their own. | Livewire 4 docs warn that a second copy of Alpine breaks initialisation. |
| **D-12** | **Preline JS is re-initialised after Livewire DOM updates** (`HSStaticMethods.autoInit()` on `livewire:navigated` and after morphs). | Without this, Preline dropdowns, overlays and tabs die after `wire:navigate`. |
| **D-13** | **Public interactivity uses stateless JSON endpoints + Alpine** (lead forms, estimator, booking, chat widget), not Livewire. Throttle + honeypot + Cloudflare Turnstile. | Public pages are full-page cached (LiteSpeed). Livewire/CSRF does not survive page caching. |
| **D-14** | **Money = integer minor units (paisa) in `BIGINT`**, currency PKR. Quantities = `DECIMAL(14,3)`. All totals are computed **server-side** (`brick/math` for multiply/round). The browser never decides a total. | The old system calculated money in browser JavaScript and stored it in JSON blobs. That made reporting impossible and was easy to tamper with. |
| **D-15** | **Sent documents are immutable.** Sending a quotation creates a `quote_versions` snapshot (JSON + PDF hash). Edits after sending create a new revision (`WI-10123 R1`). | Audit trail. The client always sees exactly what was sent. |
| **D-16** | **Numbering:** Interior and Project jobs use **WI-10100+** (quotes; the invoice reuses the quote number + milestone suffix, e.g. `WI-10123-1`). Furniture uses its own counter, **WF-10050+**. Receipts use `RC-2026-0001`. Counters live in `number_sequences` with a row lock. Prefixes and start values can be changed in Settings. | Carries the existing Woodex practice forward. |
| **D-17** | **Queue = `database` driver drained by cron** every minute: `schedule:run`, which runs `queue:work --stop-when-empty --max-time=50`. No daemons. | Shared hosting cannot keep a worker running. |
| **D-18** | **Real-time = Laravel Broadcasting with a hosted Pusher-protocol service** (Pusher Channels or Ably free tier). If no key is configured, the UI falls back to `wire:poll.visible`. | Reverb needs a long-running process, which shared hosting cannot run. The fallback means the system never depends on the paid tier. |
| **D-19** | **PDF = dompdf** (pure PHP) with print-specific Blade templates. Urdu PDFs are a risk: test early, and keep mPDF as the fallback. | No headless Chrome on shared hosting. |
| **D-20** | **Auth = Laravel Fortify** (headless) with TailAdmin-styled screens. **TOTP 2FA is required** for owner, admin and accountant. | Money and personal data live in the system. |
| **D-21** | **Permissions = spatie/laravel-permission.** Roles: `owner`, `admin`, `sales_manager`, `sales`, `designer_pm`, `accountant`, `editor`, `support`. | Covers the roles found in v2.1, plus the PM and accountant roles it was missing. |
| **D-22** | **Settings = spatie/laravel-settings** (typed groups). Third-party secrets are stored **encrypted** (`encrypted` settings) or in `.env`, **never in Git**. | The old system kept 28 JSON side-files in `_private/`, and its public repo leaked credentials. |
| **D-23** | **Integrations sit behind interfaces** (`WhatsAppGateway`, `TelegramGateway`, `MetaGraph`, `LinkedInGateway`, `AiProvider`, `RealtimeBroadcaster`). Each one is switched on by entering keys in Settings and has a **"Test connection"** button. | Lets each integration be swapped or switched off without code changes. Tests use fakes. |
| **D-24** | **AI provider is abstracted.** Default: Anthropic Claude (the reference project's choice); OpenAI or Gemini optional. Each provider has a daily cost cap and per-conversation turn limits. | Keeps costs under control and avoids lock-in. |
| **D-25** | **Data migration = one-way importer** `php artisan woodex:import-v21` reading a read-only `legacy` DB connection. It supports dry-run, idempotent re-runs, row counts, money checksums and a CSV of warnings. Imported users must **set new passwords**. | Old credentials were exposed publicly. Re-runnable until cut-over day. |
| **D-26** | **SEO continuity:** all 142 URLs answer 200 with a trailing slash; non-slash requests 301 to the slash version. A CI "URL parity" test fails the build if any URL is missing. | Protects the existing Google rankings. |
| **D-27** | **Licences:** Preline free blocks (MIT + Fair Use: attribution in the footer credits page and in `docs/`), and TailAdmin (MIT). **Preline Pro blocks are used only if a Pro licence is bought** (*Pending*). | Legal safety. |
| **D-28** | **Quality gates:** Pest 5 tests, Larastan (level 5 in P0, level 6 from P1) and Pint on every push via GitHub Actions on PHP 8.4. Tests are blocking from day one; Pint and Larastan become blocking after the P0 clean-up pass. A phase is not "done" until CI is green. | No PHP runtime is guaranteed on the owner's machine. CI is the referee. |
| **D-29** | **Domains:** new app first on **`admin.woodex.com.pk`** (staff, P0–P5). The public website moves to the apex domain at the P6 cut-over. A **staging** subdomain mirrors production. | Matches D-06. The live site keeps working untouched until P6. |
| **D-30** | **Time zone `Asia/Karachi`, locale `en`; client-facing messages in English + Urdu.** Phone numbers are stored in E.164 (`+923…`); local formats are normalised on input. | Pakistan-first business. Phone is the identity key for dedupe. |
| **D-31** | **First-response SLA (P1):** the timer stops on the first outbound **call (any outcome)**, WhatsApp, email or meeting, or when a user moves the lead past New. The lead only moves New → Contacted automatically when the client was **reached** (call connected / call back, WhatsApp, email, meeting). `woodex:sla-check` runs every minute, flags each breach **once** (atomic claim), writes a timeline entry and alerts the owner plus the escalation roles (Settings → Notifications) in-app and on Telegram. Per-source targets and a manager → owner escalation chain follow with alert rules (AUT-003, P5). | Matches how the team actually works: a missed call is still a response attempt, but it is not contact. One alert per breach avoids alert fatigue. |
| **D-32** | **v2.1 importer scope by phase:** P1 imports users, clients, leads, notes and bookings; templates/quotes (P2), invoices/payments (P3), chats (P4) and projects (P8) are added to the same importer with their modules. Lead refs `V21-00123`; imported leads never start SLA timers or alerts; follow-up dates become the next action (11:00); 1 marla = 225 sq ft, 1 kanal = 4,500 sq ft. Runbook: docs/08. | Each module's data is imported when its screens exist and can be checked by the team. Lahore marla standard (225 sq ft) as used by DHA/LDA. |
| **D-33** | **Lead sources:** added `social_media`, `google`, `portal`, `event`, `outreach` and `other` (organic/offline channels the team records by hand). The original v2.1 label is kept in `source_detail`. Paid social leads keep their own sources (`facebook_lead_ad`, `instagram_lead_ad`, `linkedin_lead_gen`). | v2.1 had these sources; dropping them would lose attribution for past leads. |
| **D-34** | **Static analysis:** Larastan reads model `casts()` method bodies (`parseModelCastsMethod: true`), which removed every false positive; the codebase is clean at **level 6** and Larastan can now be **blocking** in CI. Settings classes use `@phpstan-var` for array shapes, never `@var` (spatie/laravel-settings parses `@var`). | Typed dates and enums catch real bugs (two were found while adding P1). |
| **D-35** | **Preline JS per plugin:** the admin imports only the Preline plugins it uses (now `dropdown`; add `overlay`, `tabs`, … when a screen needs them) and re-initialises them after `wire:navigate` and morphs. A small Vite plugin marks `preline/plugins/*` as side-effectful, because Preline declares them side-effect free and the bundler would drop them. | Admin JS went from ~390 KB to 44 KB (14 KB gzip). |
| **D-36** | **Assets never depend on the proxy:** pages reference their own CSS/JS/links with **root-relative URLs**, so they work under whatever origin the browser uses (the sandbox preview server rewrites absolute self-URLs, `ASSET_URL=/` there); static files are served with explicit MIME types; every inline SVG carries `width`/`height` attributes as a fallback (Tailwind classes still win). Asset checks (root-relative, 200, `text/css`) are part of the smoke test. | The holding page rendered unstyled twice in the owner's browser while every in-sandbox curl check passed: absolute URLs on a guessed preview host failed in the real browser. A page must degrade gracefully, and asset loading is verified, not assumed. |
| **D-37** | **Lead assignment = ordered rules, first match wins** (line, service, city/area, source; empty list = any). A rule assigns to a role or chosen people by **round robin** (next id after the last pick) or **fewest open leads**, skipping anyone at the rule's **workload cap**. "Working hours only" rules are skipped while the studio is closed, so an after-hours rule below them catches evening enquiries. No match → least-loaded sales, then sales manager. Taking a lead from its owner requires a **reason** on the timeline. | Matches CRM-009 with one simple mental model (top-to-bottom list) that the owner can maintain without help; per-person shift calendars are not needed for a studio of this size. |
| **D-38** | **SLA targets per source + two escalation levels.** Due time = business-hours `dueAt(source minutes)`; **holidays** (Settings → Business, `YYYY-MM-DD name` per line) count as closed days (30-day horizon covers Eid breaks). First breach → lead owner + escalation roles; still uncontacted after `sla_escalation_minutes` (default 60) → **final roles** (default owner) once (`sla_escalated_at`). | CRM-010/AUT-004: WhatsApp/chat/phone enquiries expect faster replies (10 min) than forms (15 min); moon-dependent holidays must be editable. |
| **D-39** | **Scoring rules live in Settings** (`sales.scoring_rules` + `hot_score`): base, budget band, size thresholds (largest match), service, line, city/area, timeline, and **max(source points, lead-type points)** so a referral is not counted twice. Defaults reproduce the P1 part 1 scores exactly; existing scores are not recalculated on save. | CRM-011 asks for owner-editable rules; keeping defaults identical avoids reshuffling the pipeline on deploy. |
| **D-40** | **Reminders and repeating tasks:** `woodex:reminders` (every minute) sends task reminders at `remind_at` (skipped if more than 6 h late, e.g. after downtime) and site-visit reminders at T−24 h and T−2 h (keys in `site_visits.reminders`; the 2 h reminder replaces a missed day-before one). Completing a repeating task (daily / Mon–Sat / weekly / monthly) creates the next occurrence from the due date, rolled forward past today, never duplicated. | CRM-007/008 with cron-only infrastructure; no reminder floods after an outage, no duplicate tasks when a task is reopened and completed again. |
| **D-41** | **Attachments are private.** Media library default disk = `local` (storage/app/private); files are served only by `admin/media/{media}` after `Gate::allows('view', parent)`. Allow-list by extension (photos, PDF, DWG/DXF, Excel, Word, PowerPoint), 20 MB each, WebP thumbnails for images only (no Ghostscript/FFmpeg on shared hosting), queued conversions, `nonOptimized()` (no binaries). | GLB-006; client drawings and photos must never be reachable by URL guessing, and shared hosting cannot run optimiser binaries. |
| **D-42** | **Recycle bin semantics:** deleting a contact also bins its enquiries; restoring a contact restores enquiries binned with it (1-minute window); restoring a lead restores its contact. **Erase** (owner only) anonymises the contact (name → "Erased contact #id", phones/email/address/notes/files removed, activity bodies cleared, lead messages/addresses/attribution cleared) and keeps money totals and the audit trail. | GLB-010 and privacy requests without breaking financial history or leaving orphaned leads. |
| **D-43** | **List tools pattern** (`HasSavedViews`): saved views store filters, sort, page size and columns per person and screen; a default view applies only when the URL has no query string (shared links win). CSV export streams the filtered, permission-scoped query (max 10,000 rows) with a formula-injection guard; bulk actions re-check permissions per record. | GLB-003; reusable for Contacts/Companies/Quotes without new code. |
| **D-44** | **@mentions:** `@First`, `@First Last` or `@emailname` (case-insensitive, word-bounded) of an active user notifies them in-app + Telegram after the note is committed; the author is never notified; mentioned ids are stored in `activities.data.mentions`. | GLB-005 without an autocomplete widget; works from phones and Telegram-style typing. |
| **D-45** | **Notification bell polls every 30 s while the tab is visible** (Livewire `wire:poll.30s.visible`, Alpine dropdown so polling never closes it); real-time broadcasting replaces polling in P4. A full Notifications page lists everything with an unread filter. | GLB-008 within shared-hosting limits (no websocket server until P4's broadcaster decision). |
| **D-46** | **v2.1 import from the UI is queued:** System → Data import dispatches `RunV21Import` (database queue, cron worker); progress/state in cache `woodex:import:status`; a real run needs a dry run from the last 24 h and typing `IMPORT`. The CLI (`woodex:import-v21`) stays for SSH. | SYS-006 for an owner without SSH; web requests on shared hosting time out, queue jobs do not. |
| **D-47** | **Integrations hub shows status, never secrets:** keys stay in the server `.env` (docs/06 §4); cards show configured / last success / last error from `integration_logs`, with test buttons (Telegram test message, connect webhook, test email, test v2.1 connection). Logs keep metadata only (no tokens, no message text). | SYS-005/GLB-018 while respecting D-22 (secrets never in Git or the UI). |
| **D-48** | **Admin layout geometry is CSS, not Alpine bindings:** the sidebar width is `--wx-sidebar-w` (admin.css), switched by `<html data-sidebar="collapsed">`, which an inline `<head>` script sets before first paint and the sidebar store updates on toggle. Never put layout widths/margins in `:class` bindings. Charts (`initCharts` in admin.js) claim their element before any `await`, re-fit to their box with a ResizeObserver and use whole-number ticks for small counts. | Alpine-bound margins with `transition-all` made the whole content column slide in on every page load and `wire:navigate`; ApexCharts measured during the slide, drew too wide and was rendered twice (two init paths raced). |
| **D-49** | **Public forms work as plain HTML first:** form fields are never inside `<template x-if>`; post-submit panels and error lines use `x-show` + `x-cloak` (rule in site.css and admin.css); the submit button is `disabled` until Alpine starts (forms post JSON, D-13) with a `<noscript>` hint; button labels have static text. | The holding-page lead form was an empty white card whenever JavaScript was slow or blocked, so the most important conversion point depended on a script download. |
| **D-50** | **Sandbox tooling lives in `tools/sandbox/`** (php-wasm PHP 8.4, GitHub-based resolver, preview server, smoke/asset/browser checks; no secrets, not deployed). **UI changes are accepted only after `browser-check.mjs`** (real headless Chromium: styles, JS running, no failed requests/console errors, charts, sidebar, mobile drawer, forms with and without JS) **and `iframe-check.mjs`** (D-52). | VM resets wiped tooling kept outside the repo; curl-only checks missed what the owner saw (unstyled page, empty form, double/overflowing chart). |
| **D-51** | **Sign-in redirects never land on the public site.** (1) A failed sign-in, such as a wrong password, a lockout or an empty field, goes back to its own form. `bootstrap/app.php` sets the redirect of every `ValidationException` from `login.store`, `two-factor.login.store` and `password.email` to `login`, `two-factor.login` and `password.request`; errors and old input are still flashed. (2) A signed-in user who opens a guest page goes to `admin.dashboard` (`redirectUsersTo`). (3) The auth forms submit only once per page; the guard is in `layouts/auth.blade.php` and resets on back/forward. | Laravel's fallbacks are `/` (no Referer, no session) and the route named `home`. Both are the public website when the admin runs under `ADMIN_PATH`. In the owner's preview tests, a wrong e-mail and then a double click on "Sign in" both ended on the holding page, the second time while already signed in. |
| **D-52** | **The preview must work although its proxy drops the `Cookie` request header.** Requests from the owner's browser reach the server with no cookies, even though the browser keeps them (beacon: `cookieKept=1`, `storageAccess=1`). The proxy also drops `Referer`. `server.mjs` therefore acts as the cookie jar for real browser requests through the public preview host. The key is User-Agent + Accept-Language, stored values win, and local checks are never affected; `PREVIEW_COOKIE_MEMORY=0` turns it off. The sign-in page shows a preview-only demo-account box with a one-click sign-in; `PREVIEW_LOGIN_HINT=0` hides it. `iframe-check.mjs` reproduces the Arena setup in headless Chromium: a cross-site iframe, a proxy without Referer, third-party cookies blocked, and a run where every cookie is dropped. Sandbox only, demo data only. | 2026-10-15: every request from the owner's browser started a new Laravel session, even with `Secure; SameSite=None; Partitioned` cookies, so sign-in could never stick. Checks in a normal tab could not show this. Opening the preview in a new tab would not help either, because the cookies are lost in the proxy. |
| **D-53** | **Quotation visibility follows contacts.** People with `leads.view_all` or `invoices.manage` see every quotation. Everyone else sees the quotations they own and those of leads they own (`Quote::visibleTo`, `QuotePolicy`). The rate book and templates are visible to everyone with `quotes.view`. Changing them needs the new permission **`quotes.catalog`** (owner, admin, sales manager). | Same mental model as contacts (D-21). Accounts need every quote for invoicing (P3), and sales reps must not change company rates. |
| **D-54** | **The quote builder saves every field on blur.** All changes go through `QuoteEditor`, then `RecalculateQuote` writes line totals, section subtotals, quote totals, margin and milestone amounts on the server. Enter in a quantity, rate or discount field adds a line below. Sections and lines move by drag and drop (SortableJS) or with up/down buttons. Only drafts and "changes requested" quotes are editable; that is a state check made before the permission check, because the owner passes every permission (`Gate::before`). Template quantities or rates left blank become 0 and are flagged "needs quantity/rate". The milestone plan is stored in `quotes.meta.milestone_plan`, and editing any milestone switches it to Custom. Template sections and lines are edited by building a quotation and using **Save as template**, either new or "update a template"; template details are edited on the Templates screen. Rate book lines are copied into the quote, so later rate changes never alter it. Money is no longer in the quote's activity log; sent revisions keep immutable snapshots (D-15). | Autosave means no lost work and server-only totals (QUO-004, D-14). One editor for quotes and templates means no second, half-maintained template editor. Logging every draft recalculation would flood the audit log. |
| **D-55** | **Livewire 4 `wire:model` modifiers:** a plain `.blur`, `.change` or `.enter` only syncs the browser-side value and never sends a request. Use **`wire:model.live.blur`** to save on blur. This was the old v3 `.blur`, with the value kept live in the browser so that a button click still includes it. A field that must save is checked in a real browser (`browser-check.mjs`), because `Livewire::test()->set()` bypasses the modifiers. | The first builder version saved nothing in the browser while every Pest test passed. The headless-browser check caught it before the owner did. |
