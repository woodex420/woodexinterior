# Deep QA — Woodex OS, 21 October 2026

**Scope:** every screen in the admin (45 routes), the four business chains (enquiry → estimate → quotation → invoice → payment → project), the automation scheduler, the website studio/builder, and the repository itself.

**Verdict in one line:** the engine is real and wired; the *paths between screens* were not. An enquiry could become a lead but never an estimate, the browser tab said "Woodex OS" on eight screens, demo rows had no marker, and the sidebar advertised shipped features as future phases. Those are fixed in Slice A. The remaining gaps are listed below in the order I recommend fixing them.

### Slice C — One pricing path — DONE (21 Oct)
**What was wrong.** `CreateQuoteFromEstimate` built the quotation lines straight from the enquiry's meta and never
wrote an `Estimate` row, so `quotes.estimate_id` was null on every quotation and the Estimations screen stayed
empty while estimator enquiries were arriving. The estimate — the record of what the rate book said — was
optional, and the sales team could not see the pipeline of website estimates.

**What shipped.**
| Change | What it does |
|---|---|
| `Sales\Services\EstimatorLeadDetails` | one reader for the estimator's three facts (service, area, finish) and the range the site showed; `meta.fields` / `meta.estimate` first, lead columns only for estimator rows with no meta |
| `Sales\Actions\DraftEstimateFromEstimatorLead` | writes the rate-book draft estimate for an enquiry, attributed to the lead owner (or the first active person who may manage estimates); idempotent per lead |
| `Sales\Listeners\RecordEstimatorEstimate` | on `LeadCaptured`, every estimator enquiry gets its draft immediately — the public bridge included |
| `CreateQuoteFromEstimate` | converts the enquiry's existing draft (or writes one) and links both sides (`quote.estimate_id` ↔ `estimate.quote_id`) inside one transaction; a quotation can no longer exist without its estimate |
| `estimates:backfill` | `--dry-run` and idempotent catch-up for enquiries captured before this slice |
| Hub layout | one page heading per hub screen — the duplicate "Leads / Leads" is gone |
| Estimations list | shows the rate book's service label instead of the stored key |

**Acceptance met.** A converted quotation has a non-null `estimate_id`; the estimate history is complete; the four
pre-existing demo quotations are untouched (they remain estimate-less history, and the new rule applies to
everything created from here).

**Live proof on 33143.** A real `POST /api/forms.php` — the v1 site's own endpoint — with `form=estimator`,
`area=1200`, `finish=premium` created lead `L-2026-000002` and, in the same request, `EST-2026-0007`
(draft, 1,200 sft, Rs 480,000). `estimates:backfill` (after a `--dry-run` that listed the same four) then wrote `EST-2026-0003…0006` for the
estimator enquiries already in the database. Proof rows were deleted afterwards; the screenshots are
`/tmp/woodex-run/shots/slice-c-estimations.png` and `slice-c-leads-hub.png`.

**Tests.** 11 new/updated: capture writes the draft (5), backfill dry-run/twice/unpriced (4), quotation links its
estimate (1), one heading per hub (1). Full suite `1,307 passed · 1 skipped · 7,044 assertions`; Pint clean; PHPStan 0.
