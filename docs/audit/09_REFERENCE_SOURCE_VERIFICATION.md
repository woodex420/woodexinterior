The builder's own header states the model precisely:

> Canvas: the page's own HTML in an iframe (page scripts paused while editing). Per-device styles are
> stored as JSON in `<script id="wx-style-data">` and compiled into `<style id="wx-custom-css">`
> (desktop base, tablet ≤1024px, mobile ≤640px).

That confirms the two capability gaps identified in `03` §4 as the most important:

1. **per-breakpoint styles** (desktop / tablet ≤1024 / mobile ≤640), and
2. a **canvas that edits the page's own HTML**, versus our typed-section blocks.

## 3. What this changes in the audit

- **B-05** moves from Blocked to Resolved (`01`, `03`, `08`).
- **Phase 2** can now be implemented against real behaviour: breakpoint tabs, three-panel layout,
  template library parity, and the exact style JSON shape. It does **not** mean porting the PHP API:
  our Laravel actions already provide persistence, versions and publishing.
- **No licence file** means the code must not be vendored. Treat it as a behavioural reference and
  re-implement in Livewire/Alpine. If the owner wants literal reuse, add a licence/ownership note
  first.
- The **Google Drive production ZIP** (`Woodex-Live-v2.1-Pro-Production.zip`, 28.62 MB) could not be
  fetched: `drive.usercontent.google.com` is outside the sandbox's allowed hosts and no copy exists at
  `/home/user/-marketingwoodex/`. It is not required — the repository above contains the source.
